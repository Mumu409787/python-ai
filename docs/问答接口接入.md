# 知序问答服务接入文档 · v1

接口标识：**`zhixu.qa.v1`**。适用于把知序作为其他项目的“资料问答功能”，由调用方后端通过 HTTP 请求接入。

你不必把知序源码、数据库驱动或 MCP 配置复制进另一个项目。保持知序服务运行，让另一个项目调用它即可。此接口直接复用现有检索、生成、引用、分类、会话和追踪链路。

## 1. 接入结构与使用边界

```text
其他项目网页 → 其他项目后端（身份校验、保存接入密钥）
                          → 知序 HTTP 问答接口
                          → 现有知识库与模型服务
                          → 答案、片段来源、页码、会话与追踪信息
```

- **服务标识**：JSON 顶层 `serviceId=zhixu.qa.v1`，响应头 `X-Zhixu-Service` 同值。
- **协议版本**：JSON 顶层 `apiVersion="1"`，路径包含 `/v1`。不兼容的契约变化应另开版本。
- **请求标识**：服务为每个请求生成 `requestId`，同时放在 `X-Request-Id` 响应头，用于报告问题。它不是幂等键。
- **模式**：`RAG` 知识库问答；`CHAT` 普通聊天。首版外部接口是非流式请求。
- **知识库范围**：这套知序实例的全部有效资料共享；`clientId` 不过滤文档、不提供租户权限。不同客户的私有资料需要另行设计权限与检索过滤，或分别部署实例。
- **鉴权范围**：新 `/ask` 端点使用共享 Bearer 密钥，适合相互信任的项目后端。`clientId` 由调用方填写，不是经过认证的用户身份。
- **会话范围**：以接口版本、`clientId`、`sessionId` 组成内部命名空间，原有记忆层再按 `mode` 隔离；防止不同项目意外混用同名会话。持有共享密钥的调用方仍需自行保证用户会话权限。
- **部署范围**：现有网页与资料管理接口继续保留原有行为。新接入口的密钥不会自动保护旧接口；对外部署应由网关只转发需要的路径，并使用 HTTPS、访问控制和费用限制。

## 2. 知序服务端准备

先按根目录 README 和 `运维/运行手册.md` 配好数据库、向量库、模型密钥、迁移和现有知识库。

在知序所在电脑，按 Windows 键搜索 **PowerShell** 并打开。以下命令输入到 `PS ...>` 后，每行回车，不在网页或 Python `>>>` 中输入。

当前本机目录是 `D:\Projects\知序`；其他人的目录以实际克隆位置为准：

```powershell
Set-Location 'D:\Projects\知序'
.\.venv\Scripts\python.exe scripts/setup_integration.py
```

预期输出：`Integration key configured.`；已经存在合格密钥则显示 `Existing integration key preserved.`。脚本只更新本机 `.env` 的 `INTEGRATION_API_KEY`，保留其他配置，不打印密钥，不调用模型。未找到 `.env` 时先按 README 准备配置；已有密钥不合格时手动修正，脚本不会替你覆盖。

本机 `.env` 配置示意：

```dotenv
INTEGRATION_API_KEY=此处应为脚本生成的真实随机密钥
INTEGRATION_TIMEOUT_SECONDS=180
```

密钥至少 32 字符，不能带首尾空白；留空时仅禁用外部 `/ask`，返回 HTTP 503。错误的非空配置会阻止应用启动。此密钥是**知序服务接入密钥**，不要用 DeepSeek、SiliconFlow 或 Langfuse 的密钥代替。

修改代码或 `.env` 后需要重启。仍在这个 **PowerShell** 中执行：

```powershell
.\scripts\stop_demo.ps1
.\scripts\start_demo.ps1
```

前台启动的 Uvicorn 在原日志窗口按 **Ctrl+C** 停止，再启动。若停止脚本拒绝关闭不明进程，按运行手册确认进程归属，不强行按端口杀其他服务。启动会沿用本项目已有向量维度校验，可能产生一次 embedding 调用。

若移动/改名项目后出现 `No module named python_ai`，在项目目录的 PowerShell 执行：

```powershell
uv sync --locked --reinstall-package python-ai
```

这是修复可编辑安装仍指向旧目录的方式；目录名称可以是“知序”，Python 包名称仍是 `python_ai`。若现有依赖齐全，只需重装本地项目且希望避免联网解析，可执行：

```powershell
uv pip install --python .\.venv\Scripts\python.exe --offline --no-deps --reinstall --editable .
```

离线方式需要本地已缓存构建依赖；缺缓存时恢复网络并按 README 同步环境。本次目录改名后的路径问题已使用离线重装修复。

## 3. 服务发现与健康检查

服务已启动时，浏览器直接打开：

- `http://127.0.0.1:8000/api/integration/v1/info`：服务标识、是否配置接入密钥、路径、模式、会话限制和超时预算；公开读取，不调用模型。
- `http://127.0.0.1:8000/api/health`：原有依赖健康检查，不调用生成模型。
- `http://127.0.0.1:8000/docs`：可交互接口文档，找到 `zhixu.qa.v1` 分组。
- `http://127.0.0.1:8000/openapi.json`：程序和 Agent 可读取的机器接口契约。

`info.data.enabled=true` 仅表示接入密钥已配置，不表示模型鉴权、数据库或完整问答必定成功。健康检查通过也不等于真实问答已经验收。

Swagger 中 `/ask` 的操作标识为 `zhixu_qa_v1_ask`；点击 **Authorize**，在 `ZhixuIntegrationKey` 中填写接入密钥，HTTP Bearer 工具会添加请求头。注意：点击问答的 **Execute** 会实际调用业务链路，可能产生模型费用。

## 4. 发起问答

**`POST /api/integration/v1/ask`**

请求头：

```http
Authorization: Bearer <知序接入密钥>
Content-Type: application/json
```

请求体：

```json
{
  "clientId": "my-study-app",
  "message": "42901 表示什么？",
  "mode": "RAG",
  "sessionId": "user-42-conversation-1"
}
```

| 字段 | 必填 | 规则与作用 |
| --- | --- | --- |
| `clientId` | 是 | 1～64 个 ASCII 字母/数字/点/下划线/连字符，首字符为字母或数字；建议每个项目使用固定且唯一的标识 |
| `message` | 是 | 1～4000 字符，不能只有空白；用户当前问题 |
| `mode` | 否 | 严格为 `RAG` 或 `CHAT`，默认 `RAG`；不是 URL 查询参数 |
| `sessionId` | 否 | 1～128 个 ASCII 字母/数字/点/下划线/冒号/连字符，首字符为字母或数字；不传则每次创建新会话 |

未知字段会返回 422。请使用本文中的字段，不要发送旧接口的 `useRag` 或自创 `question` 字段。

第一次不传 `sessionId`，保存响应的 `data.sessionId`；后续追问使用同一 `clientId`、同一 `sessionId` 和同一 `mode`。新建会话时不传旧编号，或生成新的随机编号。

调用方必须为不同用户、不同聊天窗口分别保存会话编号，验证归属，不要全站共用一个固定 `sessionId`。不要将真实姓名、手机号等直接编码进编号。当前默认记忆 TTL 为 3600 秒，最多保存最近 10 轮；实际值以发现接口为准。服务重启不清空仍有效的持久会话。

## 5. 成功返回、引用和无依据状态

下面是**结构示意**；答案、编号、耗时和片段内容以实际资料和调用为准。

```json
{
  "serviceId": "zhixu.qa.v1",
  "apiVersion": "1",
  "requestId": "9cbfaeece23c424197a87488b7a2e089",
  "code": 0,
  "message": "成功",
  "data": {
    "clientId": "my-study-app",
    "sessionId": "user-42-conversation-1",
    "mode": "RAG",
    "status": "answered",
    "answer": "根据资料，42901 表示…… [1]",
    "hits": [
      {
        "docId": 1,
        "chunkId": 2,
        "docName": "star-link-spec.md",
        "content": "这里是实际召回的资料原文片段",
        "score": 0.8,
        "scoreKind": "rerank",
        "sourcePage": null
      }
    ],
    "costMs": 2400,
    "usedRag": true,
    "memorySaved": true,
    "queryInfo": {
      "originalQuestion": "42901 表示什么？",
      "retrievalQuery": "42901 表示什么？",
      "rewriteStatus": "no_history"
    },
    "traceId": null,
    "traceUrl": null,
    "questionCategory": null
  }
}
```

| 字段 | 调用方如何使用 |
| --- | --- |
| `serviceId`、`apiVersion` | 确认连接的是预期服务和协议；机器客户端应校验 |
| `requestId` | 发生问题时记录它与 HTTP 状态；不是答案来源或重试去重标识 |
| `answer` | 展示给用户；默认按文本渲染，若渲染 Markdown/HTML 必须处理不可信内容 |
| `hits` | 每项是一条返回候选，答案 `[1]` 对应第一项；页码为物理页码，非 PDF 时可为空 |
| `status` | `answered`：RAG 有候选；`no_evidence`：RAG 无命中、固定拒答；`chat`：普通聊天 |
| `usedRag` | 是否走知识库模式；`true` 不代表一定找到依据 |
| `queryInfo` | 显示原问题、实际检索问题及改写状态；CHAT 时可为空 |
| `memorySaved` | `false` 时本轮答案仍可显示，但历史写入失败，下一次追问不保证记得本轮 |
| `traceId/traceUrl` | 可选追踪信息；为空不代表问答失败，Cloud 记录访问仍需对应权限 |
| `questionCategory` | 可选本地主题辅助结果，不是知识问答的标准答案或正确率 |
| `costMs` | 现有问答链路测得的耗时，单位毫秒；不是调用方完整网络往返耗时 |

`status=answered` 表示存在检索候选，不是事实正确性保证。分数也不是正确率。相同资料上传为不同格式时可以返回多个来源，不代表多个独立证据；调用方应保留来源关联而非错误地累加可信度。

知识库没有命中时仍是 HTTP 200、`code=0`，但 `data.status=no_evidence`、`hits=[]`，答案是资料不足的拒答。不要把它当 HTTP 故障；如需切换普通聊天，应清楚告知用户将失去知识库依据，再显式发送 `mode=CHAT`。

## 6. 错误与排查

新外部接入口使用标准 HTTP 错误状态；与旧 `/api/chat` 的“HTTP 200 + 非零 code”约定不同。

```json
{
  "serviceId": "zhixu.qa.v1",
  "apiVersion": "1",
  "requestId": "服务生成的请求编号",
  "code": 401,
  "message": "问答接入密钥无效或缺失",
  "data": null
}
```

| HTTP | code | 发生原因 | 怎样检查和处理 |
| --- | --- | --- | --- |
| 400/422 | 1001 | 业务参数错误 / 请求体或字段校验失败 | 看 message 中字段位置；核对 JSON、message、clientId、mode、sessionId 与长度；修正后再发 |
| 401 | 401 | Bearer 密钥缺失或不匹配 | 确认请求头带 `Bearer ` 前缀，调用方密钥与服务端一致；修改服务端配置后重启 |
| 429 | 2002 | 模型供应商限流 | 检查供应商配额与并发；稍后由用户明确重试，不立即循环发送 |
| 502 | 2001/2004 等 | 模型调用或向量化失败 | 确认服务端模型配置、余额、网络和日志；客户端不要获取或替换服务端模型密钥 |
| 503 | 503 | 外部问答未启用 | 运行 setup_integration.py 或填写 INTEGRATION_API_KEY，再重启服务 |
| 503 | 2005 | 向量库不可用 | 看 `/api/health`，检查 Docker、Qdrant 地址和容器状态，按运维手册恢复 |
| 504 | 2003 | 问答预算耗尽或模型超时 | 缩短问题，查服务耗时与供应商状态；必要时协调服务端预算和客户端/网关超时 |
| 500 | 5000 | 未预期服务异常 | 保存 requestId、发生时间和复现步骤，查看 `.demo-run/stderr.log` 或实际服务日志 |

连接被拒绝：确认知序已启动、地址与端口正确。HTTP 404：核对路径并确认重启后加载新代码；若旧进程仍运行，看到旧页面并不代表新接口已加载。

日志查看命令，在**知序电脑的 PowerShell**运行：

```powershell
Set-Location 'D:\Projects\知序'
Get-Content .\.demo-run\stderr.log -Tail 80
```

不要把含密钥或完整私人资料的日志原样发到公共平台。代理返回的 HTML、404/405 或网络中断不保证具有本文 JSON 错误结构，客户端需兼容这种情况。

## 7. Python 接入与可执行示例

提供标准库客户端 `scripts/call_zhixu.py`，可复制到其他项目，不要求安装知序包。它不自动重试，会校验服务标识；只有传入 `--message` 才会执行问答。

在调用方电脑的 **PowerShell** 中先配置调用方环境。打开知序的本机 `.env` 查看接入密钥，通过你的本地配置方式填到调用方；不要把密钥发到聊天里或写进版本库。

以下演示从知序目录运行示例，另一个项目可替换解释器和脚本路径：

```powershell
Set-Location 'D:\Projects\知序'
$env:ZHIXU_BASE_URL='http://127.0.0.1:8000'
$secret = Read-Host '请在本机输入知序接入密钥' -AsSecureString
$env:ZHIXU_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
.\.venv\Scripts\python.exe scripts/call_zhixu.py --client-id my-study-app --message '42901 表示什么？'
```

输入密钥时不回显，密钥仅进入当前窗口的进程环境；复制进其他项目时应改为该项目自己的本机配置方式。

首轮成功后复制 JSON 中的 `data.sessionId`，在同一窗口继续：

```powershell
.\.venv\Scripts\python.exe scripts/call_zhixu.py --client-id my-study-app --session-id '替换为首轮返回的编号' --message '遇到它应该怎么处理？'
```

需要普通聊天时：

```powershell
.\.venv\Scripts\python.exe scripts/call_zhixu.py --client-id my-study-app --mode CHAT --message '用一句话解释什么是数据库事务'
```

预期输出为含 `serviceId`、`code=0`、`data.answer` 的 JSON；RAG 的实际答案还取决于知序已有资料。无依据时 `no_evidence` 是正常结果。执行这些命令可能产生真实模型费用。

自己的 Python 后端也可用已有 `httpx` 客户端；以下为函数示例，调用方负责将参数与密钥传入：

```python
import httpx


async def ask_zhixu(base_url, api_key, client_id, message, session_id=None):
    payload = {"clientId": client_id, "message": message, "mode": "RAG"}
    if session_id is not None:
        payload["sessionId"] = session_id
    async with httpx.AsyncClient(timeout=210.0) as client:
        response = await client.post(
            base_url.rstrip("/") + "/api/integration/v1/ask",
            headers={"Authorization": f"Bearer {api_key}"},
            json=payload,
        )
        response.raise_for_status()  # 上层捕获 HTTPStatusError 并处理错误体
        result = response.json()
    if result.get("serviceId") != "zhixu.qa.v1" or result.get("code") != 0:
        raise ValueError("问答服务标识或业务响应不符合预期")
    return result["data"]
```

应用中可复用客户端连接池，及时关闭；密钥只在调用方后端环境读取。Java、Node 等客户端同样按 HTTP 契约接入，无需 Python 环境或 MCP。跨机器时 `127.0.0.1` 指调用方自己，应改用实际可达的 HTTPS 地址；默认启动器只监听本机，远程部署需明确配置网关和监听方式，详见运行手册。

## 8. 超时、重试、流式与文件管理

- 服务端默认总问答预算 180 秒，可通过 `INTEGRATION_TIMEOUT_SECONDS` 调整，范围大于 0 且不超过 600 秒。
- 示例客户端等待 210 秒。改变服务预算时同步修改客户端和反向代理预算；客户端网络读取超时与服务端总预算不是同一计时机制。
- 请求没有幂等去重。客户端超时、断网或上游错误后，不要自动无条件重发；之前的请求可能已经完成或保存会话，上游模型也可能已经计费。服务端已有模型客户端可能进行自身重试。
- 同一会话应串行发送追问；当前接入口不承诺并发追问的业务顺序，也没有提供撤销或任意节点续跑能力。
- 本版 `/ask` 不支持流式。原 `/api/chat/stream` 是旧内部接口，采用不同请求、鉴权和 SSE 约定，不能当作此版本的流式模式直接替换。
- 首版接入只提供问答与服务发现。资料先在知序工作台管理；原资料管理接口不受新密钥自动保护。若未来需要远程上传、删除，需单独设计受保护的管理接口。
- 不保证保留原文件下载链接。`hits` 提供片段与来源元信息，不能把 `docId` 拼成一个未定义的原文件 URL。

## 9. 给后续开发者或 Agent 的接入清单

1. 读取本文与 `/openapi.json`，确认目标服务标识为 `zhixu.qa.v1`；操作标识为 `zhixu_qa_v1_info`、`zhixu_qa_v1_ask`。
2. 确认调用方后端的 `ZHIXU_BASE_URL`、`ZHIXU_API_KEY`，明确唯一 `clientId`。不要将密钥硬编码进前端或提交到仓库。
3. 在调用方定义薄客户端：发送 POST、处理 HTTP 与业务状态、返回结构化答案，不复制知序内部业务代码。
4. 将调用方当前用户和聊天窗口映射到随机会话编号；检查会话归属，新会话独立保存编号。
5. 页面显示 `answer` 和有序 `hits`，保留页码与片段；显式处理 `no_evidence`、`memorySaved=false` 和接口失败。
6. 用调用方的 HTTP 替身验证成功、无依据、401、422、503、504、非 JSON 和网络错误；不要为了测试解析逻辑反复调用真实模型。
7. 在明确授权和用量预算内，小规模真实验收：单轮问答、同会话追问、新会话、无依据；标明用了哪些已入库资料。
8. 报告代码改动、测试证据和已知限制，尤其是共享知识库、共享密钥及非流式边界。

可向后续 Agent 提供：

> 为本项目接入知序问答。先阅读知序 docs/问答接口接入.md 和目标服务 /openapi.json，复用 zhixu.qa.v1 协议。调用只经过本项目后端；密钥从环境读取。实现会话归属、答案及来源展示、无依据状态和错误处理。沿用现有 HTTP 客户端，不复制知序内部检索代码，不主动触发真实付费问答来发现接口。先用替身完成契约测试，再按授权进行小规模真实验收。

在**知序目录的 PowerShell**执行，不需要先启动网页服务：

```powershell
Set-Location 'D:\Projects\知序'
.\.venv\Scripts\python.exe -m pytest tests/test_integration.py
```

看到 `passed` 代表外部接口契约回归通过；测试使用问答替身和可控故障，不调用付费模型，也不证明真实知识库、Cloud 或模型服务已完成验收。失败时根据测试名和断言检查对应规则；导入失败先按第 2 节修复环境。

若所有测试点通过后，pytest 在清理全局临时目录时报告 `pytest-current` 拒绝访问，可指定本次独立的项目临时目录，不需要删除系统临时目录。在同一 PowerShell 中执行：

```powershell
$testTemp = Join-Path '.demo-run' ('pytest-integration-' + [guid]::NewGuid().ToString('N'))
.\.venv\Scripts\python.exe -m pytest tests/test_integration.py --basetemp $testTemp
```

这条命令每次使用新目录；不要把 `--basetemp` 指向已有重要数据目录，因为 pytest 会管理并清理它。
