# 星链网关 API 规范

> 版本 v2.3 ｜ 最后更新 2026-08-14 ｜ 维护者：平台架构组
>
> 本文是虚构文档，仅用于 RAG 链路的测试与演示。

## 1. 概述

星链网关（StarLink Gateway）是面向内部服务的统一南北向流量入口，
承担鉴权、限流、路由与协议转换四项职责。所有对外服务必须经由网关暴露，
不允许业务服务直接监听公网端口。

网关默认监听 **8443** 端口，仅接受 HTTPS 请求，支持 HTTP/2 与 WebSocket 升级。
内部服务间调用走 9443 端口的 mTLS 通道，与外部流量物理隔离。

## 2. 认证机制

网关采用 **Bearer Token** 认证，Token 格式为 JWT，签名算法固定 **HS256**。

- 请求头格式：`Authorization: Bearer <token>`
- **Token 有效期为 2 小时**，过期后必须重新获取
- 刷新接口：`POST /auth/refresh`，用未过期的旧 Token 换取新 Token
- Refresh Token 有效期为 7 天，且**只能使用一次**（用后即失效）

Token 载荷中必须包含 `sub`（用户标识）、`exp`（过期时间）、`scope`（权限范围）
三个字段，缺少任意一个网关会直接返回 40101。

## 3. 接口清单

### 3.1 查询节点状态

```
GET /api/v2/nodes/{nodeId}
```

返回指定节点的运行状态，包括 CPU 使用率、内存占用、当前连接数与最近一次心跳时间。

### 3.2 提交任务

```
POST /api/v2/tasks
Content-Type: application/json
```

请求体需包含 `taskType`、`payload`、`priority` 三个字段。
`priority` 取值范围为 1 到 9，数值越大优先级越高，默认值为 5。

该接口是**幂等接口**，重复提交相同的 `requestId` 不会创建新任务，
而是返回首次提交时生成的任务 ID。

### 3.3 取消任务

```
DELETE /api/v2/tasks/{taskId}
```

仅能取消处于 `PENDING` 或 `RUNNING` 状态的任务。
任务一旦进入 `SUCCESS` 或 `FAILED` 终态，取消请求返回 40002。

## 4. 限流策略

网关按 **Token 维度**限流，默认配额为 **100 QPS**，允许短时突发到 **200 QPS**。

超过配额时返回 HTTP 429，并在响应头中携带 `Retry-After`，
值为建议等待的**秒数**。客户端应当读取该值后再重试，而不是立刻重发。

限流计数在滑动窗口内统计，窗口长度为 1 秒。
配额可以在控制台按应用申请上调，单应用上限为 1000 QPS。

## 5. 错误码

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| 40001 | 请求参数不合法 | 检查请求体字段与类型 |
| 40002 | 资源状态不允许该操作 | 查询当前状态后再决定 |
| 40101 | 认证失败或 Token 过期 | 重新获取 Token |
| 40301 | 权限不足 | 检查 Token 的 scope 字段 |
| 42901 | 触发限流 | 按 Retry-After 等待后重试 |
| 50001 | 网关内部错误 | 记录 requestId 并联系平台组 |

## 6. 客户端重试规范

对于**幂等接口**（如查询节点状态、提交带 requestId 的任务），
客户端应当实现指数退避重试：

- 初始退避间隔 **200 毫秒**
- 每次退避时间翻倍
- 最大重试次数为 **5 次**
- 仅对 5xx 与 429 重试，4xx 中的 40101/40301 不应自动重试

对于**非幂等接口**，重试前必须先确认上一次请求的实际执行结果，
避免产生重复副作用。

## 7. 超时与连接

- 网关侧单请求处理超时：**30 秒**
- 客户端建议的连接超时：3 秒
- 建议的读取超时：35 秒（略大于网关超时，避免客户端先断开）

超过 30 秒仍未处理完的请求，网关会返回 504，并在响应头中记录 `X-Trace-Id`。

## 8. 灰度与版本

网关支持按请求头 `X-Canary: true` 进行灰度路由，
灰度流量占比可在控制台按 1% 粒度调整。

API 路径中的版本号（`/api/v2/`）为**主版本**，仅在出现不兼容变更时递增。
向后兼容的新增字段不会提升主版本号。
