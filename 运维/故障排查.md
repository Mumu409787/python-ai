# 故障排查

所有命令在 **PowerShell** 输入；先运行 `Set-Location 'D:\Projects\python-ai'`。保留失败操作、时间、完整错误，再选择对应条目，每次修一项并复查。网页上传/问答是真实请求，会产生模型用量，避免反复点击。

## 1. 先找到错误发生在哪里

- 前台 Uvicorn：看原服务终端；后台启动器：用下面命令看相同时间的日志。
- 网页能打开：按 F12 → Network，查看失败的 /api/documents 或 /api/chat 的响应 code/message；HTTP 200 不等于业务成功。流式还要看 error/done 事件。
- 测试失败：保存第一个 FAILED/ERROR 测试位置及 traceback。
- INFO 请求日志和 stderr 中的正常启动信息不等于故障。

```powershell
Set-Location 'D:\Projects\python-ai'
Get-Content -LiteralPath '.demo-run/stderr.log' -Tail 100
Get-Content -LiteralPath '.demo-run/stdout.log' -Tail 100
```

找不到日志先核对启动方式；前台运行不会自动保存到这两个文件。

## 2. 网页打不开、依赖故障与端口占用

| 现象 | 定位及处理 | 复查 |
| --- | --- | --- |
| 8000 连接被拒绝 | 运行 start_demo.ps1；失败就查日志，优先看缺依赖、迁移版本和 embedding 探测错误 | ready 后网页可打开 |
| PostgreSQL/Qdrant/Redis 未就绪 | 打开 Docker Desktop，执行 docker compose ps、docker compose logs --tail 80 postgres qdrant redis；未运行则 compose up -d。核对 .env 的本项目端口/库名/集合 | 健康检查对应项 true |
| docker/uv 找不到 | 确认程序安装及 PATH，重新打开终端；Docker 本机完整路径见运行手册 | --version 与 compose ps 正常 |
| 密码验证失败 | 核对 .env 与实际 PostgreSQL 用户/库；已有数据卷不会因改 Compose 密码自动更新数据库密码 | 连通后再启动，不删除数据卷重置 |
| address already in use / WinError 10048 | 先看网页是否已有正常本项目服务；有则复用。否则用下面只读命令查进程身份，确认后在原终端 Ctrl+C 或用所属启动脚本停止 | 重新启动只有预期服务 |
| PID 不属于本项目 | 启动器为避免误关进程而拒绝停止；记录结果并核实实际启动方式 | 不结束所有 Python/MCP 进程 |

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/health' -TimeoutSec 10 | ConvertTo-Json -Depth 5
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
```

把 OwningProcess 的实际数字填入 `Get-Process -Id 数字`，核实程序。不要以 `docker compose down -v` 排障，它会删除持久化数据。

## 3. 缺包、依赖下载及迁移失败

主环境缺包时，在本项目目录执行 `uv sync --locked`，再复现失败操作。训练环境单独执行 `uv sync --project training --locked --python 3.12`。不要把 sklearn 训练依赖装入主环境或随意删锁文件、升级所有包。

下载超时先核实网络及实际包源；本机曾有全局 uv 包源干扰，可用项目缓存和显式镜像恢复：

```powershell
uv --cache-dir .demo-run/uv-cache sync --no-config --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

该备用命令可能重写锁文件中的包源；不要额外加 --upgrade，执行后用 `git diff -- uv.lock` 核实版本没有意外变化。通常优先 --locked。No solution found 要核对声明与锁文件版本，不用安装不明同名包替代。

迁移版本不匹配：先备份，再运行 ` .\.venv\Scripts\python.exe scripts/migrate_db.py`，用 `python -m alembic current/check`（python 替换本项目解释器）核对。已有业务表却无版本时，按运行手册的 --adopt-existing 接管流程处理。结构不一致时保留具体列/约束差异，不能手工 stamp 或删表蒙混通过。

## 4. 上传、PDF、OCR 与编码错误

| 现象 | 定位及修改方式 | 复查 |
| --- | --- | --- |
| PDF 解析失败 / 1001 | 阅读器打开原文件；损坏则重新下载/导出有效 PDF。普通文字改扩展名不会变 PDF；broken.pdf 是故障演示样本 | 先试星链 MD，再试有效 PDF |
| 文件不是 UTF-8 | VS Code 右下角编码 → 通过编码重新打开选原编码，显示正确后通过编码保存 → UTF-8，保留原副本 | 转换后上传 |
| 类型不支持 / 1004 | 导出支持的 UTF-8 文本、有效 PDF 或文字图片，不仅改扩展名 | 小文件上传成功 |
| 过大、页数/像素超限 | 按章节/页拆有效文件，或降低图片分辨率。默认 20MiB、30 页、每页 2000 万像素 | 先随附样本，再原件 |
| OCR 引擎未找到 | 核实 tesseract.exe 路径；自定义安装在 .env 设置 TESSERACT_PATH，重启 | 环境检查 executable 正常 |
| 语言无法加载 | 核对 OCR_TESSDATA_DIR 下有 chi_sim.traineddata 和 eng.traineddata；项目与系统语言目录可能不同 | 环境脚本列出两种语言 |
| OCR 超时 | 清晰正向扫描、拆页、降低分辨率；仅确认资源充足后调整每页20秒/总60秒预算并重启 | 上传小样本成功 |
| 加密 PDF、多帧图片 | 合法解密并导出普通 PDF；多帧图逐帧导出，不静默只取第一页 | 正确页数与正文 |
| 无文字或错字 | 对照原图，改善扫描质量；必要时人工校对并存 UTF-8 文本上传。复杂表格、手写未验证 | 核对关键编号/事实，不只看入库成功 |

OCR 识别本地执行，后续 embedding 仍收费。示例“苍鹭”可能被认成其他近似字；回答引用错误 OCR 名称时，需修正提取内容/资料，不能当作真实服务差异。原生文字很多且包含图片文字的同一页，不保证图片区域全部自动 OCR。

## 5. 模型调用与检索问题

| 现象 | 定位及处理 | 复查 |
| --- | --- | --- |
| 401、Key 无效 / 2001 | 对话查 DEEPSEEK_API_KEY；向量化/重排查 SILICONFLOW_API_KEY。确认供应商与账户，编辑 .env 后重启 | 一次短问题/小文件成功 |
| 429 / 2002 | 停止连续请求，稍后单次重试；查对应供应商额度、并发与速率限制 | 不能无限重试 |
| 超时 / 2003、向量化失败 / 2004 | 看日志对应服务和异常，核对网络、账户、超时配置；确需延长才调整并重启 | 小样本复测 |
| Qdrant/写入失败 / 2005、2006、入库失败 / 5001 | 查容器和库状态；维度错误核对 EMBEDDING_MODEL/EMBEDDING_DIM/原集合。优先恢复兼容配置，切换模型需规划新集合与重入库 | 不清空旧集合，恢复后上传并检索 |
| 资料不足、无来源 | 确认知识库模式、文档 DONE、当前数据库/集合正确；先问原文明确信息，检查实际改写问题及召回候选 | 星链 Token 为2小时且有来源；其他语料单独评估 |
| 42901 原文有却未召回 | 向量比整段语义，原文出现编号不保证超过0.45；检查混合开关、BM25词项及切片。可在独立诊断查询查看过滤前候选，不能凭空编造分数 | 不为单题盲目降低全局阈值 |
| 多个相同内容引用 | PNG、扫描PDF、混合PDF是三份文件；不同字节不合并，当前没有跨文件近似文本合并。三个引用不等于独立佐证 | 查看文档ID和页码；单独测试时只保留所需临时样本 |
| 删除后旧答案还显示 | 已显示的聊天正文不会自动抹去；新建会话再查新引用。其他重复文件仍可能命中 | 来源不含被删文档ID，不要求其他来源也消失 |
| 1002 文档不存在、1003 正在处理 | 刷新列表确认是否已删；等待当前上传/删除完成再重试，避免并发重复操作 | 列表/状态一致；长期冲突看日志 |

检索分数不是正确率。已有资料未通过候选条件与“文件根本没入库”是两种问题；本项目没有通用保证所有库外问题都无命中，仍需核实检索片段能否支持答案。

## 6. 会话、Langfuse 和分类器

| 现象 | 定位及处理 | 复查 |
| --- | --- | --- |
| 同会话记不住 | 核对 session 编号、RAG/CHAT 模式、TTL和保存状态；默认查 PostgreSQL，只有 MEMORY_BACKEND=redis 才查 Redis | 同模式两轮，再真正重启后回忆 |
| 会话未保存 | 查 PG权限/磁盘/异常；memorySaved=false 不能当保存成功。修复后再发完整一轮 | “会话已保存”；过期及旧Redis历史不自动恢复 |
| 刷新后看不到聊天正文 | 前端只保留会话编号，不持久化正文；后端历史按 TTL 仍可读取 | 同编号继续问，别点新会话 |
| 模型说无法持久记忆 | 可能是通用模型措辞，按实际重启回忆及保存状态验证外部检查点 | 不凭一句模型回答判数据库失败 |
| Langfuse 不见 trace | 核对是否 enabled、两项凭据及区域；只填密钥或 health 配置true不是接收证明；等后台发送后看自己的Cloud项目 | 发一次新问题并查看新trace |
| Langfuse 401/403 | 核对同项目 Public/Secret Key 是否填反及区域，修改后重启 | Cloud 收到记录 |
| Langfuse 429/网络失败 | 查Cloud限额与区域网络，避免高频查询；旧trace REST接口可限流，用UI或v2 observations。问答不应因此失败 | 追踪单独恢复，不更换DeepSeek Key |
| Cloud 没有正文 | 默认 LANGFUSE_CAPTURE_CONTENT=false，属预期；确需上传正文自行调整并重启，只影响之后请求 | 注意所选资料范围，不上传私有正文 |
| 分类 unavailable | 核对 CLASSIFIER_MODEL_PATH 对应JSON存在及数值有效；恢复版本管理模型或按 training/README 重训 | classify API恢复，不影响主问答 |
| 分类错误/未确定 | 它只判断主题，不回答问题；小样本教学模型已有误分类。补人工核验真实数据并保留独立测试，不强迫每题归类 | 评估指标与错例一起看 |

## 7. Ruff 与 pytest：怎样查、怎样改

`would be reformatted` 是 Python 排版问题，与 PDF、OCR 文字或业务断言无关。格式命令实际会改写代码：

```powershell
.\.venv\Scripts\python.exe -m ruff format src tests scripts evaluation alembic training/train_classifier.py
.\.venv\Scripts\python.exe -m ruff format --check src tests scripts evaluation alembic training/train_classifier.py
.\.venv\Scripts\python.exe -m ruff check src tests scripts evaluation alembic training/train_classifier.py
```

Ruff check 报错要看 `路径:行:列 + 规则号`，例如 F401 未使用导入、F821 未定义名称。在编辑器 Ctrl+G 跳到该行；用 `python -m ruff rule F401` 查说明（使用项目解释器）。可先对输出指定文件运行 `ruff check --diff` 预览，再 `ruff check --fix` 应用默认安全修复；剩余人工按规则修，不盲目加 noqa/unsafe-fixes。改后重新 check、format --check、相关 pytest。

pytest 看最后 summary 和第一个失败的 traceback，找到本项目文件行号；ModuleNotFoundError 先查依赖，连接拒绝先查服务，AssertionError 对照预期/实际行为，不能删断言换绿色。默认离线详细复现：

```powershell
Remove-Item Env:RUN_SERVICE_TESTS -ErrorAction SilentlyContinue
Remove-Item Env:RUN_OCR_TESTS -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe -m pytest -x -vv --tb=short
```

具体失败项从输出复制，例如 ` .\.venv\Scripts\python.exe -m pytest tests/test_demo.py -vv`。需服务/OCR的测试按功能验收开启对应标志，不能将 skipped 当成功。修复后先单项、再完整回归；warnings 与 failed/ERROR 区分。

如果仅在 Codex 沙箱中出现缓存目录或训练基础 Python 的 permission denied，需在允许访问相应路径的环境核实，不能直接判断模型损坏。pytest 可用项目内临时目录：

```powershell
.\.venv\Scripts\python.exe -m pytest --basetemp=.demo-run/pytest-local -o cache_dir=.demo-run/pytest-cache-local
```
