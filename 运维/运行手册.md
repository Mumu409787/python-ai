# 运行手册

适用：Windows PowerShell，本机项目 `D:\Projects\python-ai`。换机器先克隆项目并把下列路径换成实际位置。所有终端命令都输入在 PowerShell 的 `PS ...>` 提示符后，每行按 Enter；不是网页问答框、浏览器地址栏或 Python `>>>`。如果原终端正在前台运行服务，另开一个 PowerShell 输入检查命令。

## 1. 环境要求

| 环境 | 用途 | 是否必须 |
| --- | --- | --- |
| Python 3.14 + uv | 主服务和锁定依赖 | 必须 |
| Docker Desktop/Compose | PostgreSQL 5432、Qdrant 6335/6336、Redis 6380 | 本地默认部署需要；也可使用自行管理且配置匹配的服务 |
| DeepSeek、硅基流动 API Key | 对话、向量化、重排 | 真实上传及问答需要 |
| Tesseract + chi_sim/eng | 本地图片与扫描页 OCR | OCR 需要，纯文本不需要 |
| Langfuse Cloud 项目凭据 | 问答调用追踪 | 可选；未配置不阻断问答 |
| Python 3.12 独立训练环境 | 重新训练分类器 | 重训需要；网页已有 JSON 模型，无需先训练 |
| Node.js | 前端 SSE 自动化测试 | 测试该部分需要；网页运行不需要 Node 服务 |

PostgreSQL 容器带 pgvector 扩展，但本项目检索实际使用 Qdrant。不要把存在该扩展理解为实现了两套向量检索。

## 2. 首次配置

在 **PowerShell** 逐行输入：

```powershell
Set-Location 'D:\Projects\python-ai'
uv sync --locked
if (-not (Test-Path -LiteralPath '.env')) { Copy-Item -LiteralPath '.env.example' -Destination '.env' }
notepad .env
```

在打开的编辑器填写 `DEEPSEEK_API_KEY`、`SILICONFLOW_API_KEY`。已有 `.env` 不会被覆盖。需要追踪时填同一个 Langfuse 项目的 Public/Secret Key 和对应区域 `LANGFUSE_HOST`。默认关闭正文上报，`LANGFUSE_CAPTURE_CONTENT=false`。保存后关闭编辑器；不要把密钥作为聊天消息。

打开 Docker Desktop 并等引擎就绪，再在 **PowerShell** 输入：

```powershell
docker compose up -d
docker compose ps
.\.venv\Scripts\python.exe scripts/check_upgrade_env.py --services
```

三个容器应 healthy；检查 `services.*.ok` 为 true。本机 CLI 不在 PATH 时可这样执行：

```powershell
& "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin\docker.exe" compose ps
& "$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin\docker.exe" compose up -d
```

`check_upgrade_env.py` 只读，不调用收费模型、不迁移表；退出码 0 仅代表盘点完成，具体查看字段。训练环境未安装时 `training.runtime.ok=false` 不代表已导出分类模型无法推理。`cloudAuthenticationVerified` 始终 false，因为该脚本不发 Cloud 鉴权请求；真实 trace 接收以 Cloud 为准。

### OCR 安装

依照 [Tesseract Windows 安装说明](https://tesseract-ocr.github.io/tessdoc/Installation.html) 安装本地引擎及英文 eng、简体中文 chi_sim 数据。默认位置为 `C:\Program Files\Tesseract-OCR\tesseract.exe`。Python 包不包含引擎，仓库也不包含本机 `.tools` 语言数据。

在 **PowerShell** 检查：

```powershell
& 'C:\Program Files\Tesseract-OCR\tesseract.exe' --version
& 'C:\Program Files\Tesseract-OCR\tesseract.exe' --list-langs
```

应看到 `eng`、`chi_sim`。自定义安装在 `.env` 设置 `TESSERACT_PATH`；语言数据如放在自定义目录，设置 `OCR_TESSDATA_DIR`。本机已经补齐项目 `.tools/tessdata`，应用优先使用该目录，所以系统默认 `--list-langs` 可能不同；以项目环境检查的语言结果为准。修改配置后重启主服务。

## 3. 迁移与备份

**空库首次初始化**：依赖服务已运行后，在 PowerShell 执行：

```powershell
.\.venv\Scripts\python.exe scripts/migrate_db.py
```

**已有数据库**：升级前先备份，再执行迁移：

```powershell
.\.venv\Scripts\python.exe scripts/backup_db.py
.\.venv\Scripts\python.exe scripts/migrate_db.py
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic check
```

当前期望 `0002_source_page (head)`，check 应无新升级操作。重复 upgrade 不重复建表。备份输出 `.demo-run/backups` 下唯一 `.dump` 绝对路径，二进制直接写入，不经过 PowerShell 文本管道；只适用于本项目默认 Compose PostgreSQL，配置不符会拒绝。它不备份 Qdrant 或 Redis。

若首次接管以前 `create_all` 建出的旧库，先备份、核实库名与原有结构，再执行 ` .\.venv\Scripts\python.exe scripts/migrate_db.py --adopt-existing`。结构匹配才接管；不匹配保留报错并排查，不能靠手工 stamp、删表或 downgrade base 消除差异。本机已经接管，不需重复。

Checkpoint 在 `python_ai_memory` 独立 schema，由官方 saver 初始化；业务 document/chunk 表由 Alembic 管理。应用启动只检查业务迁移版本。

### 备份恢复的范围

生产级恢复需要 PostgreSQL、Qdrant 的一致备份和演练，当前项目没有实现统一快照或一键恢复。不要把只有 PostgreSQL 的备份直接覆盖到现有业务库并假定向量一致。先恢复到新的隔离库、核对文档/片段/迁移，再安排向量恢复或从原文件重新入库；原始文档需要自行保留，本系统没有原文件下载存储。`pg_restore` 的 `--clean` 和迁移降级可能删数据，不作为常规排错命令。

## 4. 启动、停止、重启

日常环境已配置好时，在 **PowerShell** 输入：

```powershell
Set-Location 'D:\Projects\python-ai'
.\scripts\start_demo.ps1
```

`Project is ready` 表示就绪，`already running` 表示已有服务。浏览器打开 http://127.0.0.1:8000/；开发者接口文档为 /docs。脚本隐藏后台运行，关闭终端或网页不会停止服务。

停止：

```powershell
Set-Location 'D:\Projects\python-ai'
.\scripts\stop_demo.ps1
```

看到 `Stopped this project application (PID ...)` 表示停止；脚本核对 PID、解释器和应用模块，仅停止自己记录的项目进程。`has already exited` 表示已退出；`No launcher PID file was found` 只是没有记录，不能证明服务不存在。

重启：先执行停止命令，等完成，再执行 ` .\scripts\start_demo.ps1`，等 ready。验收持久记忆时，先等回答显示“会话已保存”，保留原浏览器页面，不刷新、不点新会话、不换模式，重启后继续追问；Docker 及数据库保持运行。

前台运行的另一种方式：

```powershell
.\.venv\Scripts\python.exe -m uvicorn python_ai.main:app --host 127.0.0.1 --port 8000
```

终端持续显示日志属正常情况。停止前台服务在该终端按 **Ctrl+C**，等出现退出日志和命令提示符。之后可以改用后台启动器，不要同时启动两份占用同端口的服务。

## 5. 日常检查与费用

后台日志：

```powershell
Get-Content -LiteralPath '.demo-run/stderr.log' -Tail 100
Get-Content -LiteralPath '.demo-run/stdout.log' -Tail 100
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/health' | ConvertTo-Json -Depth 5
```

健康检查中看各服务布尔值；`langfuseConfigured` 只表示配置存在，不能证明 Cloud 接收。`memoryBackend` 默认 langgraph。Redis 仅为可选旧记忆后端，旧历史不会自动迁入检查点。

启动会产生一次真实 embedding 维度探测；上传产生 embedding 用量，知识库问答涉及 embedding/重排/生成，有历史时还可能多一次改写。无命中不调用生成模型；普通聊天调用 LLM。本地 OCR/分类不产生相应模型 API 费用，浏览网页、查列表及健康检查也不调用模型。SDK 重试可能增加实际请求次数。

服务与账户配置变更后先重启，再做一次小样本验证。故障处理见 [故障排查](故障排查.md)，回归见 [功能验收](功能验收.md)。
