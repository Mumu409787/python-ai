# 功能验收

项目 python-ai（知序），更新于 2026-10-13。先按 [运行手册](运行手册.md) 启动，再在浏览器打开 http://127.0.0.1:8000/。网页“一步步验收”提供 13 个对应案例。

上传和真实问答使用模型 API，产生用量；网页快捷按钮只填入问题，点击发送才请求模型。下面的测试样本位于项目 data/samples，保留用于回归与演示，不是自己的业务资料。

案例 01：上传与去重
1) 点击左侧“载入星链网关示例”。这是项目现有的虚构测试语料。
2) 等待出现“入库成功”或“内容已存在”，记录文档 ID、片段数。
3) 再点一次同一按钮。
通过标准：第二次显示“内容已存在”，ID 相同，列表不出现重复文档。
已有语料会直接去重，这是正常结果；不要为展示首次入库而删除已有文档。

案例 02：答案与原文对应
1) 选择“知识库问答”，输入“访问 Token 的有效期是多久？”并发送。
2) 预期事实：访问 Token 有效期为 2 小时，不要和 7 天的 Refresh Token 混淆。
3) 点击答案里的 [1] 等引用序号，展开右侧完整片段。
通过标准：答案事实正确，有来源标注，片段中确实写有 2 小时。
不同运行的答案措辞、片段顺序和分数可能变化；分数不是答案正确率。

案例 03：资料之外的问题
1) 在只有网关语料的知识库问“推荐几家好吃的火锅店”。
2) 无命中时应返回“根据现有知识库资料，无法回答该问题。”，来源为 0。
通过标准：没有编造餐厅；无命中时直接固定拒答。
如果你已经上传了餐饮资料，请换成库中没有涉及的问题。
单凭网页不能证明是否调用过生成模型；“无命中不调用 LLM”由回归测试验证。

案例 04：流式与非流式
1) 开启“流式输出”，问“网关侧单请求处理超时是多少秒，超时后返回什么？”
2) 预期事实：30 秒，超时返回 504。
3) 关闭“流式输出”，再发送同样的问题。
通过标准：流式逐步显示正文；非流式一次展示完整结果；两者事实正确且有依据。
页面耗时来自后端 costMs；网络与模型排队会波动，不用于证明优化提速。
如需测试中止，可在生成过程中点击“停止生成”；若后端已经完成，可能已保存该轮。

案例 05：多轮记忆
1) 选择“普通聊天”，点击“新会话”。这里不会做知识库检索。
2) 发送“请记住我的毕业设计代号是青竹-472。”
3) 在同一会话发送“我的毕业设计代号是什么？”
4) 预期回答包含“青竹-472”。再点“新会话”，发送同样追问，对比是否仍有依据。
通过标准：同会话能利用上一轮；新会话不会携带旧历史。
刷新保留浏览器会话编号，但网页不持久化聊天正文；服务器 PostgreSQL 检查点历史仍按 TTL 保留。
两种模式使用不同会话编号。新会话切换编号，不删除 PostgreSQL 中旧会话。

案例 06：删除与检索
1) 已提供临时验收文件 `D:\Projects\python-ai\data\samples\acceptance-test.md`，
   其中写有“苍鹭测试服务端口是 18743”。它与原有星链网关示例放在同一目录。
2) 在浏览器工作台的文档上传区域选择或拖入该文件，等待入库成功；
   然后在网页问答框输入“苍鹭测试服务端口是多少？”并发送。
3) 先确认答案及来源确实引用这份临时文档，再仅删除该文档。
4) 新建知识库会话，再问同样问题。
通过标准：列表里无临时文档，后续来源不再包含它。
若还有其他资料，系统仍可能返回其他命中，不能把“不拒答”直接当作删除失败。
不要删除自己的业务文档。界面删除会同时删除对应向量，需要明确确认。

案例 07：错误反馈
1) 上传损坏的 PDF，例如把普通文字保存为 broken.pdf 后上传。
2) 预期显示 PDF 解析失败，不出现“入库成功”。
3) 纯空白问题会在页面阻止；直接请求 API 也应返回参数错误 1001。
通过标准：错误明确显示，输入内容不会被当成完整成功回答保存。
并发、限流、超时、部分写入不建议在共享服务上人为制造；使用下面的自动化回归验证。

案例 08：混合检索与精确标识
1) 回到工作台，确认服务状态栏显示“混合检索”，载入星链网关示例。
2) 选择“知识库问答”，新会话，在网页输入 `42901` 并发送。
3) 预期回答是触发限流；点击引用，原文中应出现错误码 42901 和处理建议。
4) 另可新会话询问“/auth/refresh 有什么作用？”，检查引用中的接口路径。
通过标准：相关资料能被召回且有依据。原向量方案也可能答对，不能只靠单题声称提升。
来源分数标注“向量 / 融合 / 重排”，不同类型不能直接比较，分数不是正确率。

案例 09：查询改写与多轮追问
1) 工作台选择“知识库问答”，点击“新会话”，保持流式开启。
2) 输入“访问 Token 的有效期是多久？”，等待回答完成，预期 2 小时。
3) 在同一会话输入“那刷新用的呢？”，不要点击“新会话”。
4) 查看第二轮答案下方的检索问题，应补全 Refresh Token 的有效期问题；
   答案应包含 7 天，原文还有只能使用一次的限制。
5) 关闭流式，再追问“它能用几次？”，应检索 Refresh Token 的使用次数并回答一次。
通过标准：实际检索问题补全了上下文，答案与来源匹配；原问题仍保存在会话中。
改写模型输出会变化，不能要求逐字相同。首轮提示“首轮使用原问题”；
失败提示“改写失败，使用原问题”，不把改写故障冒充成功。
当前记忆后端没有历史时不会改写；若刷新页面，正文不保留，但相同会话编号的检查点历史可能仍存在。

配置与回退：在 VS Code 中通过“文件 → 打开文件”打开项目根目录 `.env`，
添加或修改 `HYBRID_ENABLED=false` 可恢复纯向量召回；
添加或修改 `QUERY_REWRITE_ENABLED=false` 可关闭改写。
修改后按[运行手册](运行手册.md)在 PowerShell 执行 ` .\scripts\stop_demo.ps1`，停止完成后执行 ` .\scripts\start_demo.ps1`，等 ready 再刷新网页确认状态栏；不要将 `KEY=false` 当 PowerShell 命令执行。
恢复功能时将对应配置改回 `true` 并重启。BM25 本地运行不调用额外模型；
有历史的 RAG 每轮最多一次改写调用，SDK 重试可能增加底层请求，产生模型用量和额外等待。
超时上限默认 8 秒；失败回退原问题。没有改写服务可用时仍能直接检索。

## 自动化验证

在另一个 **PowerShell** 窗口，进入项目目录后逐行输入：

```powershell
Set-Location 'D:\Projects\python-ai'
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check src tests scripts evaluation alembic training/train_classifier.py
.\.venv\Scripts\python.exe -m ruff format --check src tests scripts evaluation alembic training/train_classifier.py
node --test tests/frontend_sse.test.mjs
```

默认测试不连接真实服务，不调用付费模型；服务与 OCR 测试默认跳过。已安装 Tesseract、语言包与运行中的本项目服务时，可在同一 PowerShell 开启联调：

```powershell
$env:RUN_SERVICE_TESTS = '1'
$env:RUN_OCR_TESTS = '1'
.\.venv\Scripts\python.exe -m pytest
Remove-Item Env:RUN_SERVICE_TESTS
Remove-Item Env:RUN_OCR_TESTS
```

即使测试失败，也执行最后两行清理开关。迁移测试创建自己的随机数据库，需要当前账号具备创建测试数据库权限；测试不应指向生产环境。期望 passed，开启联调后不能将 skipped 当作通过。具体失败定位及修复见 [故障排查](故障排查.md)。
