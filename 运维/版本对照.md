## 1. 从哪里输入命令，怎么启动

打开 Windows 开始菜单，输入 **PowerShell**，打开「Windows PowerShell」或「终端」里的 PowerShell 标签页。下面的命令全部在这个终端窗口中输入，不是在网页的提问框、浏览器地址栏或 Python 的 `>>>` 中输入。

依次复制执行以下两组。脚本会后台启动服务，终端出现 ready 后即可打开网页；已经运行时不会重复启动。

```powershell
Set-Location 'D:\Projects\python-ai'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_demo.ps1
```

```powershell
Set-Location 'D:\Projects\python-ai-baseline'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_demo.ps1
```

浏览器打开 **http://127.0.0.1:8000/compare**，可以在同一页操作两份真实工作台。屏幕较小时两侧上下排列；点击「独立打开」可用两个浏览器标签查看。两个页面都显示 PostgreSQL、Qdrant、Redis 就绪后开始验收。

## 2. 先对比 `42901`

1. 确认两侧文档列表都有 `star-link-spec.md`，状态为「已入库」。建立对照时已复制现有资料，不需要重新上传。
2. 两侧都选择「知识库问答」，各点一次「新会话」。保持两边的流式开关一致。
3. 分别发送完全相同的 `42901`，等待回答完成。
4. 比较回答和右侧来源。旧逻辑仅靠向量相似度，短错误码可能低于阈值而拒答；新逻辑可以用 BM25 补回含错误码的片段。
5. 回到资料原文核对：`42901` 对应触发限流，应遵守 `Retry-After`。实际回答文字由模型生成，重点看事实和引用，不要求逐字一致。历史结果摘要见本目录的 `验证记录.md`；详细原始资料已移至本机学习归档。

## 3. 再对比追问

两侧各开新会话，先发送「访问 Token 的有效期是多久？」，等回答完成，再发送「那刷新用的呢？」。第二轮前不要点新会话。

旧版检索直接使用「那刷新用的呢？」；新版会尝试补全 Refresh Token 并在答案下显示实际检索问题。资料中 Refresh Token 有效期为 7 天、仅可使用一次。旧版已有生成时的历史记忆，不能假定它每次追问必定失败；需要观察实际来源和回答。改写增加一次模型请求，也可能失败或超时回退。

## 4. 怎么关闭、重启

仍然在 **PowerShell** 输入。以下命令分别只停止所属工程脚本启动并记录的进程。

```powershell
Set-Location 'D:\Projects\python-ai-baseline'

```

```powershell
Set-Location 'D:\Projects\python-ai'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop_demo.ps1
```

重启：先执行对应工程的停止命令，再执行第 1 节对应的启动命令。关闭网页或终端窗口不会自动停止后台服务。脚本若提示 PID 不属于本工程，会拒绝停止，避免误关其他程序。

## 5. 启动失败怎么查、怎么处理

先进入出问题的那个工程目录，在 PowerShell 输入：

```powershell
Get-Content .\.demo-run\stderr.log -Tail 60
```

- 提示虚拟环境缺失：在**对应工程目录**执行 `uv sync --locked`，完成后重新启动。不要把主工程 `.venv` 的路径写进对照版。两份工程已有各自的虚拟环境。
- PostgreSQL/Qdrant/Redis 显示不可用：先启动项目原有的数据库容器或服务，再重新启动网页服务。不要为了排错删除数据库、集合或执行清空索引的命令。
- `Address already in use` 或端口被占用：先在该项目运行 `stop_demo.ps1`；如果脚本没有记录或拒绝停止，在 PowerShell 输入 `Get-NetTCPConnection -LocalPort 8001 -State Listen | Select-Object LocalPort,OwningProcess`（新版改为 8000），再用 `Get-Process -Id 查询到的数字` 确认程序，避免按端口盲目结束进程。
- 模型超时、鉴权失败：查看上述日志，对照自己的 `.env` 检查模型服务和密钥；不要把 `.env`、API Key 或密码发给别人。本目录的故障排查.md有更详细的逐层排查步骤。
- 对照版提示数据库或集合配置不符：它固定使用 `python_ai_baseline` 数据库和 `python_ai_docs_baseline` 集合。不要改成新版数据库；检查是否在 PowerShell 中设置过同名环境变量，移除错误覆盖，再启动。

## 6. 独立保存范围与比较限制

代码、虚拟环境、PostgreSQL 数据库和 Qdrant 集合均分开保存。Redis 服务器共用，但对照版使用 `baseline:chat:session:` 前缀，与新版默认 PostgreSQL 检查点及可选 Redis 历史分开；浏览器会话也按不同端口隔离。模型账号和数据库服务实例共用，不会重复部署容器。

复制使用现有向量，不重新向量化文档。建立时记录语料、向量及代码指纹，见对照工程 `baseline-manifest.json`。复制后的新版新增、删除和代码修改不会自动同步到对照版；将来比较时要先核对语料、模型和参数是否仍一致。

对照工程另有 `baseline-source.zip`，保存封存时的源码、说明、案例和验收记录，排除了密钥、虚拟环境与运行日志。若以后误改了对照代码，可先备份被改的文件，再与压缩包中对应文件比较恢复；不要用新版代码覆盖对照版，也不要因此重建数据库。

**版本来源说明：** BM25 和查询改写加入前的改动没有独立 Git 提交，因此对照工程是从当前工程还原此前的检索与问答编排行为，保留既有稳定性修复，再加版本标识和资料写保护。它不是最初未修复项目的逐字历史快照。还原范围与文件校验值记录在 manifest 中。对照工程内历史说明、旧评测记录仅作档案，以本指南和实际运行状态为准。
